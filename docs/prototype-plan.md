# Plan corto — prototipo para validación de CAI

## Objetivo
Una experiencia visual coherente de landing, comunidad y administración, navegable en un navegador y con datos ficticios.

## Secuencia de implementación
### P0 — Preparar frontend
- Inicializar React + TypeScript + Vite.
- Crear layout, rutas y estilos base.
- Adoptar una identidad CAI consistente con la referencia previa.
- Añadir aviso visible «Prototipo / datos ficticios».

### P1 — Landing
- Hero, navegación, presentación de CAI, programas, metodología, testimonios ficticios debidamente identificados, contacto.
- CTA de acceso a comunidad.
- Diseño móvil y escritorio.

### P2 — Comunidad
- Feed con tarjetas de logros, fotografía de muestra no identificable, etiquetas de tipo de publicación.
- Perfil de muestra y formulario de publicación simulado.
- Estados pendiente/aprobado.

### P3 — Administración
- Lista de solicitudes de ingreso ficticias.
- Cola de publicaciones pendientes.
- Aprobar/rechazar con estado de UI reversible o reiniciable.

### P4 — Demo y validación
- Revisar flujo end-to-end; capturar incidencias.
- Demostrar en móvil/escritorio.
- Registrar comentarios del cliente y convertirlos en Issues.

## Fuera de esta etapa
Backend, datos privados reales, subida efectiva de contenido, cuentas reales, pagos, notificaciones y autorización productiva.

## Referencia existente
La landing anterior vive en un repositorio diferente, propiedad de un integrante del equipo. No copiar automáticamente su estructura; adaptar diseño y recursos con atribución adecuada.
